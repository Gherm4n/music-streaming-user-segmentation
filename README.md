# Music Streaming User Segmentation: A Comparative Study of K-Means and Agglomerative Hierarchical Clustering

A university-level unsupervised learning project. For a complete walkthrough with figures and presentation guidance, see [PROJECT_EXPLANATION.md](PROJECT_EXPLANATION.md). For a short summary of results, see [the final report](results/reports/final_report.md).

## 1. Project overview

This project clusters 50,000 synthetic music streaming users on their listening behaviour, using K-Means and Agglomerative Hierarchical Clustering (CAH). It compares the two methods and tests whether the resulting segments reflect real structure.

## 2. Problem statement

Streaming platforms often want to divide users into behavioural segments. However, a clustering algorithm always returns clusters, even from data with no groups. So the problem is not only how to produce segments, but also how to determine whether they mean anything.

## 3. Research question

Can K-Means and Agglomerative Hierarchical Clustering identify meaningful and interpretable user behavior segments in a music streaming platform?

## 4. Objectives

1. Understand the dataset and its characteristics.
2. Identify meaningful user behaviour patterns.
3. Compare K-Means and CAH.
4. Determine suitable cluster counts with appropriate evaluation methods.
5. Interpret clusters with descriptive profiles.
6. Compare the algorithms on quality, computational cost, interpretability and stability.
7. Produce clear visualizations and conclusions.
8. Explain the limitations, especially those due to the synthetic data.

This is not a supervised churn prediction project.

## 5. Dataset

- **Size:** 50,000 users and 18 columns, with no missing values or duplicates.
- **Nature:** synthetic, with no data dictionary, so column meanings are inferred. The original file name (`spotify_user_behavior_realistic_50000_rows.csv`) mentions Spotify, but the data says nothing about real Spotify users.
- **Contents:** demographics, account details, inactivity, ad interaction, listening behaviour, ratings and preferences.
- **Location:** `data/raw/music_streaming_users.csv`. The dataset is excluded from version control by `.gitignore`.

## 7. Methodology

1. **EDA:** data quality, distributions and relationships between variables.
2. **Preprocessing:** feature selection without leakage, then scaling.
3. **K-Means:** k from 2 to 10, followed by selection on several kinds of evidence.
4. **CAH:** linkage comparison on a reproducible sample in Notebook 04, then Ward on all users. `scripts/course_metrics.py` repeats the comparison of Ward, average, complete and single linkage on all users, with the CPCC.
5. **Reference test:** the same pipeline on 10 datasets with each column shuffled independently, which cannot contain joint structure. This was added to the original plan because the EDA found the features to be almost independent. `scripts/course_shuffle_test.py` repeats it on all users with silhouette, R² and the Ward jump only.
6. **Profiling:** segment descriptions in original units, plus tests against variables not used in clustering.
7. **Verification:** Notebook 06 recomputes key results from the saved files.

## 8. Preprocessing decisions

| Decision | Reason |
|---|---|
| All 50,000 rows kept | No missing values or duplicates; outliers are believable and odd cross-column combinations cannot be proven to be errors |
| Four input features: listening hours, playlists, skips, suggestion rating | They describe behaviour and satisfaction with suggestions |
| Identifiers, dates, demographics and outcome-like columns excluded | Avoids leakage and circular conclusions; they are used only after clustering |
| No `log1p` | The features are not meaningfully skewed, and the transform makes their shapes worse |
| StandardScaler | Gives each feature equal weight; outliers are rare and believable |
| Mixed representation: one-hot genre and device, kept at 0/1 | A comparison only; each categorical variable carries about the same total variance as one numeric feature |
| Tenure and skips per hour used only for interpretation | They add no useful behavioural information to distances |

## 9. K-Means

K-Means alternates between assigning users to the nearest centroid and moving each centroid to the mean of its users. This project uses `k-means++`, 20 restarts and a fixed seed.

## 10. CAH

Agglomerative clustering starts with each user alone and repeatedly merges the closest clusters, producing a dendrogram that can be cut at any k. Standard algorithms would need 10 GB for the distance matrix on this data, so Ward linkage is fitted with the vector-based algorithm in `fastcluster`. On a sample, its partitions were identical to those from SciPy and scikit-learn.

## 11. Evaluation metrics

- **Silhouette:** higher is generally better.
- **Davies-Bouldin:** lower is generally better.
- **Calinski-Harabasz:** higher is generally better.
- **Adjusted Rand Index:** agreement between partitions, used for stability and sensitivity.

No metric alone proves that clusters are meaningful. Metrics were read together with cluster sizes, interpretability and the reference test.

## 14. Main results

Both final models use k = 5, the same four features and all 50,000 users.

| | K-Means | Ward CAH |
|---|---:|---:|
| Silhouette (all users) | 0.186 | 0.103 |
| Davies-Bouldin | 1.321 | 1.631 |
| Calinski-Harabasz | 10,675 | 7,238 |
| Subsample stability (ARI) | 0.801 | 0.350 |
| Cluster sizes | 16.2% to 22.9% | 13.3% to 28.8% |

**K-Means segments:** Light Listeners (22.94%), Heavy Listeners (22.39%), Playlist Builders (19.35%), Frequent Skippers (19.11%), Low-Rating Users (16.22%).

**Ward segments:** Low-Skip Listeners (28.76%), Frequent Skippers (27.21%), Low-Rating Users (16.25%), Light Listeners (14.50%), Playlist Builders (13.28%).

**Conclusions:**

- **The segments are interpretable,** and K-Means gives the clearer, more repeatable description.
- **There is no evidence of natural groups.** Features are almost independent (largest |r| of 0.008, excluding the inactivity flag), and of 54 comparisons with shuffled data, 46 fall inside the shuffled range, 2 are better and 6 are worse.
- **Segments do not relate to outside variables.** The largest effect size is Cramér's V = 0.0145, and none of 26 tests is significant, so no segment can be linked to churn or conversion.
- **Agreement between the algorithms is moderate** (ARI 0.306).

## 15. Limitations

- The data is synthetic, so findings do not apply to real users.
- There are no ground-truth segments.
- Internal metrics can reward useless partitions.
- Results are sensitive to scaling and feature selection.
- The ordinal rating is treated as numeric.
- PCA plots show only 50.3% of the variance.
- All four linkages have a CPCC below 0.60 on all users (average 0.478, complete 0.379, Ward 0.351, single 0.262), so none of the trees preserves the original distances well.
- Column meanings and the tenure snapshot date are assumptions.

## 16. Future work

- Apply the pipeline to real user data.
- Add methods able to conclude that no clusters exist, such as Gaussian mixtures with BIC.
- Explore richer features, or Gower distance for mixed data.
- Compare with density-based clustering such as HDBSCAN.
- Study how segments change over time, if temporal data becomes available.
